# Australian Energy Market Commission (AEMC)

> The AEMC is the independent statutory rule maker for Australia's energy markets — it makes and amends the National Electricity Rules (NER), National Gas Rules (NGR) and National Energy Retail Rules (NERR), runs market reviews, and advises the Energy and Climate Change Ministerial Council. It operates no market systems and holds no consumer data; AEMO operates the market and the AER enforces. AEMC publishes no developer portal and no documented API, but its Energy Rules application is backed by an undocumented, entirely anonymous JSON API that serves the complete versioned text of all three rule books.

This file was generated by the API Evangelist enrichment pipeline on 2026-07-27 from AEMC's public surfaces and from live probes of that API. method: generated. AEMC does not publish an llms.txt (/llms.txt is blocked at the edge with HTTP 403).

## APIs

- [AEMC Energy Rules API](https://energy-rules.aemc.gov.au/): Undocumented, anonymous JSON API at https://energy-rules.aemc.gov.au/api/v1 serving versioned rule text — rule versions with PDF/DOCX artefacts, table of contents, per-clause content, full-text search and the defined-terms glossary. No key, no OAuth. 304 NER versions, 115 NGR, 65 NERR as at 2026-07-27. Not documented, supported or advertised by AEMC; may change without notice.

## Context for agents

- AEMC is the rule maker, not an operator or a data holder. For Australian market and system data go to AEMO; for retail offer data go to the AER; for a consumer's own energy data go to the Consumer Data Right (Treasury designates, ACCC regulates, retailers are data holders, AEMO is the gateway). AEMC is not a CDR data holder.
- On 18 December 2025 AEMC made a final rule giving consumers and their AEMO-accredited representatives a right to real-time smart-meter data. AEMO must publish the technical procedures by 30 November 2026; the meter obligation commences 30 November 2028. Nothing callable exists for it today.
- Every Energy Rules API path is keyed by the rule version **id** (e.g. 803), not the version number (e.g. 251). Passing the version number returns HTTP 404.
- Rule text and glossary definitions are returned as HTML strings; sanitise before use, and always cite the rule book, version number and clause index.
